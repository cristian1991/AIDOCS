# brainstorming

Use when the task is ambiguous, architectural, risky, or has multiple plausible designs.

Do:
- ask focused clarifying questions when requirements are genuinely unclear
- compare 2-3 approaches and recommend one
- identify the main failure modes or edge cases
- match existing project patterns unless there is a strong reason to diverge
- get approval before large or risky implementation changes

Do not:
- force design ceremony on obvious micro-tasks
- prescribe execution workflow or delegation policy
- block implementation when the task is already clear and low-risk
