# Secure CI Model

This document describes the intended GitHub Actions security model for AIDOCS, especially for public/community pull requests.

## Core Rule

Public/community pull requests must be treated as untrusted code execution attempts.

They may change:

- build scripts
- package install hooks
- filenames
- benchmark inputs
- docs content
- prompts or text that later gets processed by AI systems

## Public CI Rule

Public PR workflows must:

- run with minimal permissions
- avoid secrets entirely
- avoid self-hosted runners
- avoid private test suites
- avoid private fixtures or corpora
- avoid any privileged follow-up that executes PR-produced code or artifacts

## Private Validation Rule

Private tests and private benchmark corpora must never be exposed to public PR authors.

Private validation should be:

- maintainer-triggered
- isolated from public fork PR execution
- reported back only as coarse pass/fail or category summaries

## Workflow Pattern

### Public PR CI
- trigger: `pull_request`
- token: read-only
- secrets: none
- scope: compile/lint/smoke/public benchmark set only

### Trusted Post-Run Reporter
- trigger: `workflow_run`
- may comment on PR
- must not execute artifact contents from untrusted workflows
- should only report coarse public CI status

### Private Validation
- must happen outside the untrusted public PR workflow path
- should use maintainer gating and private infrastructure/repo context

## Hard Rules

- Never use `pull_request_target` to checkout and test untrusted PR code.
- Never run public PR code on self-hosted runners.
- Pin actions to full commit SHAs.
- Keep workflow permissions explicit and minimal.
- Treat artifacts from untrusted PR workflows as untrusted data.
- Never execute binaries or scripts generated by untrusted PR workflows in privileged contexts.
- Keep AI-assisted PR analysis advisory-only unless it is fully unprivileged.

## Required Repo Settings

These settings should be enforced outside workflow files:

- require approval for first-time fork workflow runs
- protect `.github/workflows/**` with CODEOWNERS review
- restrict Actions permissions to the minimum practical default
- disable self-hosted runners for public PR execution
- require branch protection and review on workflow changes

## Private Test Caveat

AIDOCS uses a private/public split.

That means:

- public CI can prove public compatibility and public CLI/runtime health
- private CI protects behavioral knowledge encoded in private tests
- public PR authors should never gain visibility into the private test suite just by submitting code

## Summary

The goal is not “run everything automatically.”

The goal is to make public contribution safe by default, while preserving stronger private validation for maintainers.
